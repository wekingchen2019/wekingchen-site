推荐系统是互联网最核心的技术之一。过去 7 年，我从召回排序的工程实践出发，逐步深入到算法创新与产品落地的交叉地带。这篇文章是对这段经历的回顾与思考。

## 从召回开始

2019 年入行时，推荐系统的标准范式是「召回 → 粗排 → 精排 → 重排」。我在亿级用户的产品上打磨这套 pipeline，对倒排索引、向量召回、多路召回融合有了深刻理解。

### 倒排索引与向量召回

倒排索引是经典的信息检索方法：

```python
# 倒排索引示例
inverted_index = {
    "推荐系统": [doc1, doc3, doc5],
    "深度学习": [doc2, doc4],
    "特征工程": [doc1, doc2, doc6],
}
```

向量召回则通过 embedding 空间中的最近邻搜索实现语义匹配：

```python
import numpy as np

def vector_recall(query_embedding, doc_embeddings, top_k=10):
    """基于余弦相似度的向量召回"""
    similarities = np.dot(doc_embeddings, query_embedding)
    top_indices = np.argsort(similarities)[-top_k:][::-1]
    return top_indices
```

## 排序的演进

从 LR 到 GBDT 再到 DeepFM、DIN，排序模型的演进本质上是**特征工程自动化**的过程。

| 模型 | 年份 | 核心创新 | 局限性 |
|------|------|----------|--------|
| LR | 2010 | 简单高效 | 特征交叉需手动 |
| GBDT+LR | 2014 | 自动特征交叉 | 泛化能力有限 |
| DeepFM | 2017 | 端到端学习 | 召回侧信息缺失 |
| DIN | 2018 | 用户兴趣建模 | 序列建模能力弱 |
| BERT4Rec | 2019 | 序列建模 | 计算成本高 |

## AI Native 的转向

LLM 的出现改变了游戏规则。推荐系统不再只是「给用户推什么」，而是「如何理解用户的真实意图」。

> 技术深度是基础，但真正的竞争力来自于将技术与商业价值连接的能力。

这要求算法工程师具备更强的**产品思维**和**商业理解**。

## 结语

7 年下来，最大的体会是：算法不是目的，解决问题才是。技术选型要服务于业务价值，而不是为了用而用。
